# Self-made-els-latex-template

A customized two-column LaTeX template for Elsevier journals.

## 1. About This Project

- Based on the official Elsevier LaTeX template (`els-cas-templates.zip`).
- Modifications have been made to `cas-dc-template-main.tex` to better suit the writing habits of Chinese authors.
- This project focuses on template optimization and minimalism, showcasing only essential content. For advanced typesetting needs, please search the web or use AI tools (highly recommended).

## 3. Usage

- **Main file naming convention**: The main TeX file must end with `-main` (e.g. `cas-dc-template-main.tex`). `compile_all.bat` automatically scans for `*-main.tex` in the current directory as the compilation entry point.
- Download the archive and import it into an online TeX compiler (e.g., Overleaf, TeXPage). Set the `*-main.tex` file as the main compilation file and compile using **pdfLaTeX**. The magic comments at the top of the main file let most editors auto-select the correct build steps:

  ```tex
  % !TEX program = pdflatex                 % compiler: pdfLaTeX
  % !TEX root = cas-dc-template-main.tex    % main file (auto-switch when editing sub-files)
  % !BIB program = bibtex                   % bibliography: BibTeX
  ```
- Download and extract the archive, then open the `*-main.tex` file in a local TeX compiler (e.g., TeX Studio, or VS Code with the LaTeX plugin). Set it as the main file and compile using **pdfLaTeX**.

> **Note:** Even if author info, abstract, body text, etc. are written in separate sub-files, you must still switch to the `*-main.tex` file for compilation. Otherwise, errors will occur.

- **Generating submission files (Graphical Abstract / Highlights separated, double-blind supported)**

  The Elsevier submission system typically requires "Graphical Abstract" and "Highlights" to be uploaded as separate files, and some journals require a double-blind manuscript. This repository uses the **same main file** together with build rules to generate 5 PDFs (plus 1 editable Word file) in one go:

  - `{name}-full.pdf` — Body + Graphical Abstract + Highlights (full version)
  - `{name}-without-abstract.pdf` — Body only (no Graphical Abstract / Highlights)
  - `{name}-blind.pdf` — Double-blind manuscript with author names, affiliations, author notes, running author, and CRediT hidden
  - `{name}-graphical-abstract.pdf` — Graphical Abstract only (standalone, no body)
  - `{name}-highlights.pdf` — Highlights only (standalone, no body)
  - `{name}-highlights.docx` — Editable Word Highlights file, including the paper title

  Edit Highlights in the root-level `0.Highlights.tex`; both the PDF and Word outputs read from this single source. Author, abstract, main-text, and figure files are also kept in the root directory so submission systems can recompile everything from one folder.

  **Option 1 (recommended): one-click latexmk build (a single "Build" click in your editor)**

  The root `.latexmkrc` uses latexmk's custom rules to handle multi-version PDF generation. Set the build tool to latexmk (default in TeXstudio / VS Code LaTeX Workshop / TeXworks), open `*-main.tex` and hit "Build" once — all 5 PDFs above are compiled **incrementally**:

  ```bat
  latexmk -pdf cas-dc-template-main.tex
  ```

  Notes: `*-main.tex` is auto-detected in the project root (same rule as `compile_all.bat`); only stale variants are rebuilt on each run. For daily writing, just build `*-main.tex` and you get the fast body-only version by default.

  **Option 2: compile_all.bat (Windows one-click script, additionally produces Highlights Word)**

  Recommended workflow (Windows, PowerShell or CMD):

  1. Ensure LaTeX (MiKTeX / TeX Live) is installed and configured, and that `pdflatex` can be run from the command line.
  2. Name your main file with the `-main` suffix (e.g. `my-paper-main.tex`) — the script detects it automatically.
  3. In the project root directory, double-click or run:

  ```bat
  compile_all.bat
  ```

  Note: The script runs pdfLaTeX + BibTeX two to three times for each version to ensure cross-references, tables of contents, etc. are complete, and additionally calls `make_highlights_docx.ps1` to produce the editable Highlights Word file.

  To troubleshoot compilation errors: open `compile_all.bat` and remove `>nul` from the end of each command line to see the full log.

- **Submission-system (Editorial Manager etc.) upload checklist**: the submission system only keeps the files you upload, so upload everything listed under "Required" below (all other helper files are not needed):

  **Required (source files):**

  - `cas-dc-template-main.tex` — main file (the compilation entry on the submission system)
  - `0.Highlights.tex`, `1.Author.tex`, `2.Abstract.tex`, `3.MainText.tex` — sub-files
  - `cas-refs.bib` — bibliography database

  **Required (figures):**

  - `ga-figure.pdf` — graphical abstract (needed by the full / graphical-abstract builds)
  - `simple-png.png` — figure in the main text

  **Already built into the submission system, do not upload**: `cas-dc.cls`, `cas-common.sty`, `cas-model2-names.bst`, and the `thumbnails/` icon folder (`cas-email.jpeg` etc.).

  **Not needed**: `.latexmkrc`, `compile_all.bat`, `make_highlights_docx.ps1`, `clean_latex.bat`, `README.md`, `README_EN.md`, `doc/`, compiled PDFs, and the `cas-dc-template-main-{version}.tex` entry files.

  > Submission systems usually run pdfLaTeX + BibTeX over the main file automatically; after uploading, check the build log for any `File '...' not found` errors.

## 4. Important Notes

> The main file must be named with the `-main` suffix (e.g. `cas-dc-template-main.tex`). Both `compile_all.bat` and `.latexmkrc` auto-detect `*-main.tex` as the compilation entry. The three magic comments at the top of the main file make sure editors use pdfLaTeX, run BibTeX on the main file, and switch back to the main file when editing sub-files:
>
> ```tex
> % !TEX program = pdflatex
> % !TEX root = cas-dc-template-main.tex
> % !BIB program = bibtex
> ```

> Tested with TeXstudio 4.8.9 (git 4.8.9): while building the PDF with the `*-main.tex` file, do **not** switch to a sub-file, as this may cause the compilation to fail.

> For daily writing convenience and faster compilation, the template defaults to outputting **body-only (without Graphical Abstract / Highlights)**. The template uses LaTeX core `\newif` standard boolean switches — five of them: `\ifFULL`, `\ifWITHOUTABSTRACT`, `\ifGRAPHICALONLY`, `\ifHIGHLIGHTSONLY`, `\ifBLIND` (used with plain `\if...\else...\fi`, so no group side effects). To output the full version by default, edit the "conditional compilation switches" block at the top of `*-main.tex`:

> ```tex
> \FULLtrue                  % Full version (includes Graphical Abstract and Highlights)
> % \WITHOUTABSTRACTtrue     % Default: body-only (no Graphical Abstract / Highlights, faster for daily writing)
> ```
>
> Scripts and the command line can override the defaults via `\def\XXX{1}\input{...}` (as used by `compile_all.bat` and `.latexmkrc`); the template translates those into the corresponding boolean switches, so no source edits are needed to pick a version.
>
> Note: the `\ifBLIND` switch takes effect *before* `\documentclass` (it selects the `doubleblind` class option). Enable the blind version by passing `\def\BLIND{1}` on the command line (as the `blind` variant in `compile_all.bat` / `.latexmkrc` does), or by editing lines 4–6 at the top of `*-main.tex` — do not set it in the switch block below the document body.

> Use `\cref{}` to reference figures, tables, and equations — the type is automatically added.

> Use `\cite{}` to cite references.

> Use `\lipsum[1-3]` to generate 3 random paragraphs of placeholder text.

> The template comes pre-configured with the `algorithm2e` package (`[ruled,vlined]` style); a complete usage example is included in `3.MainText.tex`.

> **ORCID Display Mode Toggle**: The template supports two ORCID display styles. Switch by changing one line in `*-main.tex`:
>
> ```tex
> \newif\ifORCIDicon
> \ORCIDicontrue    % Icon mode: green ORCID icon shown next to author names (default, recommended for submission)
> % \ORCIDiconfalse % Footnote mode: traditional footnote style (ORCID(s): ... at page bottom)
> ```
>
> - **Icon mode** (default): A green ORCID vector icon appears right after each author's name and before the affiliation superscript. The icon is clickable and links to `https://orcid.org/`. In icon mode, no ORCID footnote appears at the page bottom.
> - **Footnote mode**: Matches the original Elsevier template behavior — all authors' ORCIDs are listed in a footnote as `ORCID(s): 0000-... (Author Name)`. To switch, comment `\ORCIDicontrue` and uncomment `\ORCIDiconfalse`.
